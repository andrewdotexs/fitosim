fitosim

Motore scientifico Python per la simulazione FAO-56 del bilancio idrico e chimico di piante in vaso.

v0.1.0 Python ≥ 3.10 stdlib only (core) 1366 test verdi layer feedback fase A MIT License

Questo documento è la guida per chi sviluppa fitosim: contiene la struttura del codice, i contratti pubblici dei tre layer architetturali (science, domain, io), le convenzioni di stile, e le istruzioni per testare e contribuire. Per l'uso da utente finale, fare riferimento a docs/fitosim_user_manual.docx.

1. Panoramica

fitosim modella il bilancio idrico e chimico giornaliero del singolo vaso domestico ed estende lo standard FAO-56 con capacità specifiche del giardinaggio in vaso che i modelli per il pieno campo non coprono:

  • geometrie reali del vaso (forma, materiale, colore, esposizione);
  • sottovaso come secondo serbatoio accoppiato al substrato;
  • miscele di substrati personalizzati via compose_substrate;
  • modello chimico (massa salina, pH, EC derivata) con coefficiente nutrizionale Kn;
  • bilancio indoor con microclima della stanza (Room + sensore WN31);
  • selettore "best available" del metodo di evapotraspirazione (Penman-Monteith fisico → standard FAO-56 → Hargreaves-Samani).

Sopra al modello del singolo vaso, fitosim espone un dashboard operativo: il Garden orchestra più vasi, la persistenza SQLite conserva la storia, gli eventi pianificati e le previsioni anticipano gli interventi, e il sistema di allerte trasforma le previsioni in raccomandazioni concrete.

Domain confinato Il dominio in cui la libreria sa fare bene il suo lavoro è il vaso domestico singolo o un piccolo gruppo di vasi su balcone, su scala temporale giornaliera, per piante individualmente identificabili con substrati di parametri noti. Fuori da questo dominio (parcelle di pieno campo, controllo elettrovalvole al minuto) i risultati sono poco affidabili.

2. Architettura

2.1 I tre layer

La libreria è organizzata in tre layer con dipendenze unidirezionali: io → domain → science. Il modello scientifico non conosce né l'orchestrazione né la persistenza: puoi sostituire SQLite con PostgreSQL senza toccare nulla del FAO-56.

Layer 1 — base

science/

Funzioni pure FAO-56 esteso: bilancio idrico, ET, dual-Kc, fisica del vaso, chimica del substrato, radiazione, e il layer di feedback/calibrazione (fase A).

Dipendenze: stdlib + radiation interno.

Layer 2 — orchestrazione

domain/

Modello di dominio: Pot, Garden, Species, Room, Alert, ScheduledEvent, WeatherDay.

Dipendenze: science.

Layer 3 — adapter

io/

Persistenza SQLite, serializzazione JSON, adapter sensori (Ecowitt, Open-Meteo, HTTP-JSON, fixture CSV) che implementano i Protocol.

Dipendenze: domain, science.

2.2 Mappa delle dipendenze interne

All'interno di science/ la maggior parte dei moduli è standalone (funzioni pure indipendenti); fanno eccezione balance, et0, calibration, nutrition, indoor e behavioral_calibration, che consumano altri moduli.

science/ (base FAO-56) ├── balance ← et0 (EtMethod), substrate (Substrate, RAW) ├── dual_kc (standalone) ├── et0 ← radiation (per Ra astronomica) ├── fertigation (standalone) ├── indoor ← domain.room (LightExposure) ├── nutrition ← domain.species (Species) ├── pot_physics (standalone) ├── radiation (standalone) ├── saucer (standalone) └── substrate (standalone) science/ (layer feedback, fase A) ├── calibration ← balance (Ks), substrate ├── phenology (standalone) ├── behavioral_calibration ← domain.species (Species) ├── lysimeter (standalone) └── calibration_resolution (standalone; adapter duck-typed) domain/ ├── species (standalone) ├── weather (standalone) ├── scheduling (standalone) ├── room (standalone) ├── alerts ← pot ├── pot ← species, substrate, science.* ├── garden ← pot, room, scheduling, alerts, scheduler ├── scheduler ← pot, scheduling └── (alerts.py) ← pot io/ ├── persistence ← domain.*, science.substrate ├── serialization ← domain.*, science.substrate └── sensors/ ├── types (stdlib) ├── errors (stdlib) ├── protocols ← types ├── ecowitt ← io.ecowitt (legacy), types, errors, protocols ├── openmeteo ← io.openmeteo (legacy), types, errors, protocols ├── http_json ← types, errors, protocols └── fixtures ← types, errors, protocols

2.3 Principi di design

  • Zero dipendenze runtime nel core. Tutto gira con la stdlib di Python. Dev-deps (numpy, matplotlib) solo per test e validazione.
  • Funzioni pure dove possibile. In science/, ogni funzione è (input) → output deterministica.
  • Dataclass frozen=True per risultati e value-object; mutabilità solo per Pot.state_mm e Room.current_microclimate.
  • Stato canonico minimo + viste derivate. Il Pot ha solo 4 campi di stato dinamico (state_mm, salt_mass_meq, ph_substrate, saucer_state_mm); tutto il resto è property calcolata on-demand.
  • Layout src/ per evitare import accidentali dal working dir.
  • Tracciabilità del metodo via dataclass come EtResult (porta con sé il metodo usato per il calcolo).
  • Protocol duck-typing per i sensori: adapter custom non devono importare nulla da fitosim.
  • Unità metriche fisse: °C, mm, m/s, MJ/m²/d, frazione 0..1 per umidità (NON percentuale), timestamp UTC.

# Clone del repository
git clone https://github.com/<tuo-username>/fitosim.git

# Install in editable mode con dev-deps
pip install -e '.[dev]'

# Esegui la suite (attesi ~1366 verdi)
python -m pytest tests/

# Subset rapido per iterazione
python -m pytest tests/test_pot.py -x -q

# Con coverage
python -m pytest --cov=fitosim --cov-report=html

In alternativa, senza installare il pacchetto: 

# Su Linux/macOS
PYTHONPATH=src python tuo_script.py

# Su Windows (PowerShell)
$env:PYTHONPATH = "src"; python tuo_script.py

pyproject.toml imposta già pythonpath = ["src"] per pytest, quindi i test girano senza setup esplicito.

4. Layer science

Funzioni pure e dataclass per il calcolo agronomico FAO-56 esteso. Ogni modulo è autonomo (quasi tutti standalone) e testabile in isolamento.

science/et0.py — Evapotraspirazione di riferimento

Tre formule di calcolo dell'ET₀ (Penman-Monteith fisico, Penman-Monteith standard FAO-56, Hargreaves-Samani) con selettore best available che sceglie automaticamente la migliore disponibile in funzione di: dati meteo presenti, parametri fisiologici della specie, robustezza attesa nel contesto.

enum EtMethod

Identifica univocamente il metodo usato dal selettore.

  • HARGREAVES_SAMANI — solo Tmin/Tmax; fallback robusto.
  • PENMAN_MONTEITH_STANDARD — coltura riferimento FAO-56 (rs=70 s/m, h=0.12 m).
  • PENMAN_MONTEITH_PHYSICAL — usa stomatal_resistance_s_m e crop_height_m della specie.
dataclass EtResult

Valore di ET₀ in mm/giorno con il metodo che lo ha generato (tracciabilità).

  • value_mm: float
  • method: EtMethod
function compute_et(weather, species, latitude_deg, current_date) → EtResult

Selettore best available: prova PM fisico → PM standard → Hargreaves nell'ordine e ritorna il primo applicabile.

Altre funzioni esposte (helper pubblici): saturation_vapor_pressure, slope_vapor_pressure, actual_vapor_pressure, atmospheric_pressure, psychrometric_constant, aerodynamic_resistance, et0_hargreaves_samani, compute_et0_penman_monteith, compute_et_penman_monteith_physical.

science/balance.py — Bilancio idrico giornaliero

Cuore dell'algoritmo: implementa l'equazione di aggiornamento del contenuto idrico del substrato secondo FAO-56. Traccia lo stato idrico giornaliero, genera flag di allerta quando si scende sotto RAW (readily available water), gestisce drenaggio come overflow.

dataclass BalanceStepResult

Esito immutabile di un passo: nuovo stato, drenaggio, flag allerta, deficit.

function water_balance_step_mm(state_mm, et_c_mm, water_input_mm, fc_mm, pwp_mm, ...) → BalanceStepResult

Versione in mm (la più usata in Pot). Esiste anche water_balance_step_theta per la versione in frazione volumetrica e water_balance_step agnostica alle unità.

function stress_coefficient_ks(depletion, raw, taw) → float

FAO-56 eq. 84: interpolazione lineare di Ks. Sotto RAW la pianta riduce la traspirazione proporzionalmente alla profondità del deficit.

science/substrate.py — Substrati e geometria

Catalogo di substrati con θFC, θPWP; utility per conversioni unità (mm ↔ θ, volume), composizione di miscele personalizzate da materiali base. Senza dubbio il modulo più ricco di utility.

dataclass Substrate

Immutabile. Campi obbligatori: name, theta_fc, theta_pwp. Opzionali per dual-Kc: rew_mm, tew_mm. Opzionali per chimica: cec_meq_per_100g, typical_ph.

dataclass BaseMaterial

Materiale "ingrediente" di una miscela: torba, perlite, pomice, akadama, sabbia, kanuma, vermiculite, fibra di cocco, terriccio universale.

function compose_substrate(name, components) → Substrate

Compone un substrato da una lista di MixComponent(material, fraction). Calcola θFC/PWP come media pesata delle proprietà dei materiali.

Catalogo predefinito: UNIVERSAL_POTTING_SOIL, PEAT_BASED, COCO_COIR, PERLITE_RICH, CACTUS_MIX.

Helper geometrici: circular_pot_surface_area_m2, pot_substrate_depth_mm, theta_to_mm, mm_to_theta, total_available_water (TAW), readily_available_water (RAW), water_volume_*.

science/dual_kc.py — Dual Kc (FAO-56 cap. 7)

Separa traspirazione (Kcb) ed evaporazione superficiale (Ke) per catturare il consumo idrico reale post-irrigazione (+15-25% nelle 24-48 h seguenti).

Funzioni pubbliche: evaporation_reduction_coefficient (Kr a due fasi, energy-limited fino a REW, falling-rate verso TEW), kcmax, soil_evaporation_coefficient (FAO-56 eq. 71), update_de (evoluzione della cumulative depletion superficiale).

Costanti: KCMAX_DEFAULT=1.20, KCMAX_FLOOR_MARGIN=0.05, DEFAULT_FEW=1.0.

science/pot_physics.py — Fisica del contenitore

Modula ETc per materiale, colore ed esposizione solare. Cattura permeabilità (terracotta) e assorbimento termico (colore).

Enum: PotMaterial (PLASTIC, GLAZED_CERAMIC, TERRACOTTA, WOOD, METAL), PotColor (LIGHT, MEDIUM, DARK), SunExposure (FULL_SUN, PARTIAL_SHADE, SHADE).

Funzione: pot_correction_factor(material, color, exposure) → float. Kp = f_material × f_color × f_exposure. Range tipico 0.43–1.43 (terracotta +30%, ombra −55%).

science/saucer.py — Sottovaso

Sottovaso come secondo serbatoio accoppiato al substrato. Risalita capillare ed evaporazione del piattino riducono la frequenza di irrigazione di circa il 10-20%.

Funzioni: capillary_transfer (trasferimento proporzionale al deficit substrato), saucer_evaporation (frazione di ET₀, default 0.4).

science/fertigation.py — Bilancio chimico

Modella mescolamento istantaneo, drenaggio salino e variazione di pH ad ogni irrigazione/pioggia. Implementa il meccanismo di "lisciviazione".

Funzioni: salt_balance_step (conservazione massa salina con drenaggio proporzionale), ph_after_mixing (media pesata con buffer da CEC), fertigation_step (orchestrazione completa).

Costanti: EC_TO_MEQ_PER_LITER=10, TYPICAL_SUBSTRATE_DENSITY_KG_PER_L=0.4.

science/nutrition.py — Coefficiente nutrizionale Kn

Modula la traspirazione in funzione dello stato chimico (EC, pH). Stress salino e pH fuori range riducono la disponibilità idrica apparente per effetti fisiologici.

Funzione: nutritional_factor(species, ec_mscm, ph) → float. Prodotto di due fattori trapezoidali (1.0 dentro range, rampe lineari ai bordi, clamp a Kn_min=0.3).

science/radiation.py — Radiazione

Calcola Ra (extraterrestre, geometry pura) e Rn (netto, bilancio energetico). Input fondamentale per Penman-Monteith e per la verifica di qualità del piranometro.

Funzioni: day_of_year, solar_declination, inverse_relative_distance, sunset_hour_angle, extraterrestrial_radiation (FAO-56 eq. 21), clear_sky_radiation, net_radiation (Stefan-Boltzmann + umidità + nuvolosità).

science/indoor.py — Radiazione indoor

Stima radiazione indoor da LightExposure. Due modalità: categoriale (fallback, no stagionalità) e continua (frazione outdoor, accurata).

Funzioni: categorical_indoor_radiation (DARK=1.5, INDIRECT_BRIGHT=4.0, DIRECT_SUN=8.0 MJ/m²/d), continuous_indoor_radiation (frazioni 5%, 15%, 40%), estimate_indoor_radiation (selettore).

Il layer di feedback — fase A I cinque moduli che seguono formano il layer di calibrazione: trasformano evidenze eterogenee (letture sensore, date fenologiche, abitudini di irrigazione, pesate) in correzioni di parametro tracciabili. Sono funzioni pure, stdlib, senza effetti collaterali: ognuna propone un delta con confidenza e spiegazione in italiano; l'applicazione è un passo separato che lavora su una copia della Species, mai sul catalogo globale. Il quinto modulo è a valle — non misura nulla, compone le proposte degli altri quando più fonti toccano lo stesso parametro. Progetto completo: docs/fitosim_feedback_layer_design.md.

science/calibration.py — Calibrazione da sensore

Due segnali distinti dallo stesso sensore, che non vanno confusi.

L'ancora. θFC e θPWP effettivi (non di letteratura) dai picchi e dalle valli della serie storica: dopo un'irrigazione con drenaggio il vaso è a capacità di campo, e qualunque cosa legga il sensore in quel momento è la lettura di FC per quel vaso. Cattura compattazione e peculiarità del singolo vaso. Funzioni: find_peaks, find_valleys, estimate_theta_fc (75° percentile), estimate_theta_pwp (10° percentile), calibrate_substrate (pipeline). Restituisce CalibrationResult.

La pendenza. Tra due irrigazioni la velocità di discesa della curva è il consumo reale; invertendo il bilancio dà il Kc effettivo del vaso: 

Kc = Σ(deplezione_mm) / (Kp · Σ(Ks_i · ET₀_i))

Il punto che decide la forma della stima: Ks si legge dalla θ osservata, non si stima. Il sensore dice a che livello idrico era il vaso ogni giorno, quindi lo stress è un dato, non un'incognita — senza questo una finestra che finisce in stress darebbe un Kc sistematicamente sottostimato. Funzioni: find_drying_windows (isola le finestre tollerando le micro-risalite da rumore ma spezzando su quelle vere), estimate_kc_from_window, calibrate_kc (mediana tra finestre). Restituisce KcCalibrationResult (kc_estimate, n_windows, confidence, window_estimates).

science/phenology.py — Gradi-giorno (GDD)

Lo sviluppo delle annuali è guidato dalla temperatura accumulata sopra una soglia base, non dal calendario: sostituire "20 giorni allo stadio MID" con "X gradi-giorno, Tbase per specie" rende la fenologia trasferibile tra climi.

function growing_degree_days(t_min, t_max, t_base, t_cap=None) → float

Media semplice modificata: Tmin viene portata a Tbase prima della media — una notte a 2 °C non manda la pianta all'indietro. t_cap opzionale tronca il contributo delle giornate torride.

Funzione di accumulo: accumulate_gdd(series, t_base, t_cap=None) somma i giorni della serie.

Perché solo le annuali Lo sviluppo delle perenni è governato anche dal fabbisogno di freddo (chill units, modello Utah): sommare gradi-giorno a una pianta che deve prima accumulare freddo per uscire dalla dormienza dà la risposta sbagliata. Le perenni si ancorano al calendario stagionale (PhenologyAnchor.PERENNIAL), non ai GDD.

science/behavioral_calibration.py — Calibrazione comportamentale

Il segnale non è una misura ma un comportamento: due signali nello stesso modulo, che insieme separano due cause che ciascuno da solo confonde.

dataclass · function IrrigationDeviation → calibrate_kc_from_behavior → Kc

Lo scostamento sistematico tra quando il modello suggerisce di irrigare e quando il giardiniere irriga davvero. Restituisce un fattore (1 / median(ratio), limitato a [0.5, 2.0]) da applicare al Kc, con una misura di consistency che scarta il giardiniere bimodale. Applicato da apply_kc_correction(species, factor) su una copia. Soglie 5/10/15.

dataclass · function AlertJudgment → calibrate_depletion_from_judgments → soglia p

Il giudizio del giardiniere sullo stato della pianta quando scatta un'allerta. Due versi opposti (allerta rifiutata / sofferenza segnalata) che delimitano un intervallo invece di essere mediati: la stima è il punto di mezzo tra il 75° percentile delle "sane" e il 25° delle "sofferenti". Un flag contradictory abbassa la confidenza quando i due gruppi si sovrappongono. Helper depletion_fraction(state_mm, fc_mm, taw_mm); applicato da apply_depletion_correction. Soglie 3/6/10.

Perché servono entrambi Lo scostamento delle irrigazioni, da solo, non distingue un Kc sbagliato da una soglia p sbagliata: entrambi producono "irriga più tardi del previsto". Il giudizio sulle allerte interroga direttamente la soglia. Insieme separano le due cause.

science/lysimeter.py — Lisimetro (ground truth)

La misura più diretta che esista: pesare il vaso. Nessuna inferenza, nessun parametro del modello nel calcolo — un vaso che perde 100 g ha perso 100 ml. È il riferimento contro cui si validano le altre fonti. Bilancio di massa: 

ET = (massa_iniziale − massa_finale) + acqua_aggiunta − drenaggio

convertito in mm dividendo per la superficie del vaso (i mm di FAO-56 sono un'altezza d'acqua). L'inversione dà Kc = ET / (Ks · Kp · Kn · ET₀).

dataclass (frozen) LysimeterInterval

Due pesate + acqua aggiunta + drenaggio + ET₀ cumulata dello stesso periodo: autocontenuto, così il confronto misura/modello non dipende da allineamenti fatti altrove. mean_ks default 1.0 — vedi il vincolo di protocollo sotto.

Funzioni: mass_to_mm, measured_et_mm (il dato grezzo, utile anche fuori dalla stima di Kc), estimate_kc_from_interval, calibrate_kc_from_lysimeter (mediana, scarti contati non nascosti). Soglie 3/5/10.

Il vincolo di protocollo Kc è definito in condizioni idriche non limitanti. Chi pesa un vaso in stress non misura Kc, misura il prodotto Ks·Kc — non separabili da una sola pesata. Il protocollo tiene il vaso nella zona di comfort (Ks = 1). E la massa cambia anche per ragioni che non sono acqua: potature, raccolta, pioggia non contabilizzata, biomassa — quegli intervalli vanno esclusi, non corretti.

science/calibration_resolution.py — Precedenza tra fonti

Alla fine della fase A lo stesso parametro può essere toccato da più fonti: il Kc ne ha tre. Quando il lisimetro dice 0.95 e la pendenza del sensore di quel vaso dice 1.20 non è per forza un conflitto — il primo descrive il vaso medio del gruppo, il secondo quel vaso lì. La regola distingue due assi che è facile schiacciare in uno:

  • scope — quanto è specifica al vaso: catalogo ⊂ cluster ⊂ vaso;
  • reliability — quanto la fonte è affidabile in sé.

Il lisimetro è ground truth sull'asse reliability, ma vive sullo scope più largo. Perciò: lo scope più specifico con una proposta usabile decide il valore del vaso (lo scope batte la reliability tra scope diversi); dentro uno stesso scope vince prima la confidenza, poi il tipo (un assoluto misurato batte un fattore inferito, evitando il doppio conteggio). I valori a ogni livello vengono restituiti entrambi: resolved_value per il vaso, catalog_value per i fratelli.

I fattori si ancorano al prior Un fattore (comportamentale) è definito rispetto a ciò che il modello prevedeva quando è stato misurato. Se il lisimetro abbassa il catalogo a 0.90 e il comportamentale dice ×1.10, applicare il fattore al catalogo darebbe 0.99 — trascinando il vaso verso la media. Ancorandolo al prior (1.00) il vaso resta a 1.10, la sua evidenza, e 0.90 torna al catalogo a parte. È il punto dove un'implementazione ingenua sbaglia in silenzio.
function resolve(parameter, prior, proposals) → Resolution

Il cuore. Le fonti eterogenee vengono ridotte alla valuta comune CalibrationProposal (scope, tipo assoluto/fattore, confidenza) dagli adapter proposal_from_lysimeter / _sensor_slope / _behavioral_kc / _dismissal. La Resolution porta resolved_value, catalog_value, applied/ignored con i motivi, il flag catalog_divergence (segnala un vaso outlier oltre il 15% di scostamento da un catalogo ad alta confidenza — visibile, non inghiottito) e una spiegazione in italiano.

Confine con The Pot Questo modulo fa solo la matematica della precedenza: non raccoglie evidenze, non conosce utenti né fingerprint, non aggrega tra persone diverse. Quella è la gerarchia di aggregazione, e vive in The Pot. The Pot decide quali proposte esistono; fitosim decide come si compongono.

5. Layer domain

Modello di dominio: Pot e Garden sono le entità centrali; tutto il resto le supporta o le compone. Le dataclass frozen=True sono value object immutabili (risultati, eventi); Pot e Room hanno stato mutabile esplicito.

domain/species.py — Caratterizzazione della pianta

enum PhenologicalStage · GrowthStage

Due vocabolari, non uno (fase A). I PhenologicalStage guidano il Kc; i GrowthStage sono osservabili e condivisi con The Pot.

  • PhenologicalStage — 3 stadi FAO-56 che pilotano il Kc: INITIAL, MID_SEASON, LATE_SEASON.
  • GrowthStage — 6 stadi botanici (valori identici al catalogo The Pot): DORMIENZA, RIPOSO, GERMOGLIAMENTO, VEGETATIVO, FIORITURA, FRUTTIFICAZIONE. Possono essere simultanei.

La traduzione tra i due vive in un punto solo: fao56_stage_from_growth_stages(...) — non una corrispondenza uno-a-uno ma una funzione.

enum PhenologyAnchor · PhenologyMethod
  • PhenologyAnchor: ANNUAL (ancorata all'impianto, può usare i GDD) · PERENNIAL (ancorata al calendario stagionale, che si ripete ogni anno).
  • PhenologyMethod: GROWING_DEGREE_DAYS · CALENDAR_DAYS · SEASONAL — quale metodo il selettore best available ha effettivamente usato.

Le perenni con ancoraggio all'impianto restavano bloccate in LATE_SEASON per sempre: da qui i due ancoraggi.

dataclass (frozen) Species

Caratterizzazione completa di una specie.

  • Kc: kc_initial, kc_mid, kc_late
  • Stress: depletion_fraction (soglia p)
  • Fenologia base: initial_stage_days, mid_stage_days
  • Fenologia (fase A): phenology_anchor, phenology_calendar (12 mesi, perenni), annual_growth_stages
  • GDD (opz., annuali): t_base_c, gdd_to_mid, gdd_to_late, t_cap_c
  • Dual-Kc (opz., tutti e tre): kcb_initial, kcb_mid, kcb_late
  • Chimica (opz., tutti e quattro): ec_optimal_min/max_mscm, ph_optimal_min/max
  • Fisiologia (per PM fisico): stomatal_resistance_s_m, crop_height_m

Property: supports_dual_kc, supports_chemistry_model, supports_gdd. Metodi: stage_at(current_date, planting_date, gdd_accumulated=None) (selettore best-available), stage_at_gdd, growth_stages_at, phenology_method, stage_at_day.

Funzioni pubbliche: kc_for_stage, potential_et_c (Kc × ET₀), actual_et_c (Ks × Kc × ET₀).

Dormienza (fase A). effective_kc(...) riduce il Kc in dormienza/riposo (DORMANCY_KC_FACTOR, REST_KC_FACTOR) ma con un pavimento di evaporazione (KC_BARE_SOIL_FLOOR = 0.20): il substrato nudo evapora comunque, e un modello che desse consumo nullo non suggerirebbe mai di annaffiare. Il pavimento vale per effective_kc ma non per effective_kcb — nel dual-Kc l'evaporazione la copre già Ke.

Catalogo: BASIL, TOMATO, LETTUCE (annuali, con soglie GDD; la lattuga non fiorisce mai), CITRUS, ROSEMARY (perenni, calendario a 12 mesi), ALL_SPECIES.

domain/pot.py — Entità centrale

Il singolo vaso reale. Concentra tutto il sapere agronomico in un'entità coerente. È l'unica classe con stato mutabile (state_mm evolve nel tempo).

enum Location · PotShape
  • Location: OUTDOOR, INDOOR
  • PotShape: CYLINDRICAL, TRUNCATED_CONE, RECTANGULAR, OVAL
dataclass Pot

Identificato univocamente da label.

Immutabili dopo la creazione: label, species, substrate, geometry (pot_volume_l, pot_diameter_cm, pot_shape), location, room_id, pot_material, pot_color, sun_exposure, rainfall_exposure, shelter_level, planting_date.

Stato mutabile: state_mm, salt_mass_meq, ph_substrate, saucer_state_mm, gdd_accumulated.

Property calcolate (derivate): state_theta, fc_mm, pwp_mm, alert_mm, ec_substrate_mscm, kp, surface_area_m2, substrate_depth_mm, substrate_dry_mass_kg, water_volume_liters, supports_dual_kc. Metodo (non property): current_stage(date).

TAW e RAW non sono property del Pot Vivono in science/substrate.py come total_available_water(substrate) e readily_available_water(substrate, depletion_fraction), e restituiscono frazioni θ adimensionali, non millimetri: per i mm si moltiplica per substrate_depth_mm. Il Pot le usa internamente per derivare alert_mm, che è la soglia già pronta in mm ed è quella che serve nella maggior parte dei casi. Per la deplezione come frazione [0, 1] c'è behavioral_calibration.depletion_fraction(state_mm, fc_mm, taw_mm), dove taw_mm è un argomento da calcolare, non un attributo da leggere.

shelter_level (ShelterLevel: EXPOSED/STANDARD/SHELTERED) modula il vento prima del selettore PM. gdd_accumulated accumula i gradi-giorno dopo ogni passo di bilancio: None significa "non sto tracciando" (degrado sicuro), distinto da 0.0 che significa "traccio da adesso" — current_stage lo passa a species.stage_at per il selettore best-available.

Metodi di evoluzione dello stato

  • apply_step(et_0_mm, current_date, rainfall_volume_l) → FullStepResult — passo completo (bilancio + pioggia + saucer).
  • apply_step_from_weather(weather, current_date, ...) — usa WeatherDay + selettore best-available.
  • apply_balance_step_from_indoor(microclimate, water_input_mm, ..., room) — versione indoor.
  • update_from_sensor(reading) → SensorUpdateResult — riconcilia con misura sensore (discrepanza modello/realtà).
  • apply_fertigation_step(volume_l, ec_mscm, ph, current_date) → FertigationResult — applicazione di soluzione fertilizzante.

Tutti i risultati sono dataclass frozen=True: FullStepResult, SensorUpdateResult, FertigationResult.

6. Layer io

Adapter di ingresso e uscita. Persistenza e serializzazione sono disaccoppiate tra loro; i sensori sono Protocol duck-typed così che adapter custom non debbano importare nulla da fitosim.

io/persistence.py — SQLite

Database operativo con storia completa degli stati. Schema versionato (attualmente v5) con migrazioni automatiche, idempotenti e difensive sull'inizializzazione.

class GardenPersistence

API CRUD per giardini, vasi, room, snapshot di stato, catalogo (specie/substrati). Costruttore: GardenPersistence(db_path). Migrazioni auto sull'inizializzazione.

Metodi principali: register_species, register_substrate, save_garden(garden, snapshot_timestamp), load_garden(name) → Garden, list_gardens(), query_states(pot_label, ...) → List[PotStateSnapshot], query_events, query_scheduled_events.

Schema v5 — persistenza della calibrazione (fase A) Perché una calibrazione che non sopravvive a un reload non esiste, la migrazione v4→v5 ha aggiunto pot_states.gdd_accumulated (nullable per design: NULL = non tracciato) e 11 colonne alla tabella specie — la configurazione fenologica (phenology_anchor, phenology_calendar_json, annual_growth_stages_json, soglie GDD) più quattro campi che predatavano la fase A e non venivano salvati (depletion_fraction, stomatal_resistance_s_m, crop_height_m, notes). La migrazione usa _table_exists/_column_exists, quindi è sicura anche su DB parziali.
dataclass PotStateSnapshot

Snapshot immutabile di uno stato vaso (per ricostruire l'andamento storico).

Eccezioni canoniche: PersistenceError (base), SchemaVersionMismatch, CatalogMissingError.

io/serialization.py — JSON

Formato di trasporto autocontenuto per backup, migrazione, condivisione (FORMAT_VERSION = 3). Non è persistenza: funzioni pure, niente file I/O, niente DB. Il chiamante gestisce file e storage. La v3 ha aggiunto i 16 campi della fase A (fenologia, GDD, e quattro che erano persi anche prima); la lettura è retrocompatibile: i campi assenti in un JSON vecchio ricadono sui default della dataclass. 

from fitosim.io.serialization import export_garden_json, import_garden_json

# Export
json_str = export_garden_json(garden)

# Import
garden = import_garden_json(json_str)

Eccezione: SerializationError per JSON malformato.

Astrazione sensori — io/sensors/

Spec sensori v1 A partire dal 2026-05-15 il layer sensori adotta la spec sensori canonica v1 formalizzata in the-pot/docs/the_pot_sensors_spec.md. Tutti gli adapter operativi (Ecowitt, Open-Meteo, HTTP-JSON, fixture CSV) restituiscono ora liste piatte di Measurement (sensor_id, timestamp, parameter, value) con vocabolario controllato (air_temperature_c, soil_theta, ecc.) e namespace custom:* per estensioni utente. I tipi legacy EnvironmentReading e SoilReading restano disponibili nel modulo io/sensors/types.py ma non sono più prodotti dagli adapter.

Due interfacce asimmetriche, Protocol runtime-checkable a zero dipendenze:

protocol EnvironmentSensor 
@runtime_checkable
class EnvironmentSensor(Protocol):
    def current_conditions(self, lat: float, lon: float) -> list[Measurement]: ...
    def forecast(self, lat: float, lon: float, days: int) -> list[Measurement]: ...

Un sensore per molti vasi (coordinate geografiche). Una stazione meteo che misura T, RH, vento e pioggia produce 4 Measurement per ogni tick con stesso sensor_id e timestamp.

protocol SoilSensor 
@runtime_checkable
class SoilSensor(Protocol):
    def current_state(self, channel_id: str) -> list[Measurement]: ...

Un sensore per un vaso (channel_id). Un WH51 produce 1 Measurement (soil_theta); un WH52 fino a 3 (θ + T + EC).

Tipo canonico Measurement (io/sensors/measurement.py)

dataclass (frozen) Measurement

4 campi, validati in __post_init__:

  • sensor_id: str — opaco lato spec, convenzione raccomandata <provider>:<device_type>[:<scope>]:<instance>
  • timestamp: datetime — obbligatoriamente timezone-aware
  • parameter: str — uno dei canonici (sotto) o prefisso custom:
  • value: float — finito (no NaN/inf), dentro il range plausibile del parametro

Validazione: MeasurementValidationError per timestamp naive, parameter sconosciuto, value fuori range.

Vocabolario canonico dei parametri

CategoriaParametriRange
Ambiente air_temperature_c, air_humidity (0..1), wind_speed_m_s, solar_radiation_mj_m2, rainfall_mm, barometric_pressure_hpa Plausibili fisici (es. -50..70 °C, 0..1.05 per θ, 800..1100 hPa)
Substrato soil_theta (0..1.05), soil_temperature_c, soil_ec_mscm, soil_ph Idem
Sistema battery_level, signal_strength 0..1 (frazione, NON %)
Extension custom:<arbitrary> (es. custom:co2_ppm, custom:et0_mm) Opachi, nessuna validazione di range

Esportati come costanti dal modulo: PARAM_AIR_TEMPERATURE_C, PARAM_SOIL_THETA, ecc., più il frozenset CANONICAL_PARAMETERS e il prefisso CUSTOM_NAMESPACE_PREFIX = "custom:". Costante di versione: SCHEMA_VERSION = 1.

Tipi legacy (io/sensors/types.py) — in deprecation

EnvironmentReading, SoilReading, ReadingQuality restano disponibili nel modulo per retrocompatibilità con codice che le importa, ma nessun adapter operativo le produce più. Saranno rimosse in una futura versione una volta che il backend di The Pot (e il dominio di fitosim) avrà migrato i suoi consumatori.

7. Testing

fitosim ha 1366 test verdi (428 sub-test) che girano in pochi secondi su laptop standard. La suite è la rete di sicurezza primaria del refactoring.

Il test che conta, per ogni fonte di calibrazione Ogni modulo della fase A ha un test di giro chiuso con verità nota: si costruisce una serie con un parametro noto e si verifica di recuperarlo. Per il lisimetro è il round-trip contro la geometria reale di un Pot (un errore di fattore 10 nella conversione grammi→mm non lo vede nessuno finché non si chiude quel giro); per la precedenza è l'ancoraggio del fattore al prior (1.10, non 0.99).

Struttura

Ogni modulo ha un test file dedicato (tests/test_<module>.py). I test seguono lo stile narrativo: test_<contesto>_<comportamento> (es. test_balance_drainage_caps_state_at_fc).

Categorie di test

CategoriaFileCosa testa
Unit scientificitest_balance, test_et0, test_substrate, ...Funzioni pure FAO-56 e helper.
Layer feedback (fase A)test_calibration, test_phenology, test_behavioral_calibration, test_lysimeter, test_calibration_resolutionRecupero di parametri noti, robustezza della mediana, guardrail di confidenza e precedenza tra fonti.
Unit dominiotest_pot, test_garden, test_alerts, ...Entità di dominio e invarianti.

Per i test degli adapter HTTP, fitosim usa fixture JSON statiche in tests/fixtures/: no mock, no monkey-patching pesante, parsing puro su payload reali catturati.

8. Convenzioni di codice

Naming

  • Snake_case per funzioni, variabili, moduli; PascalCase per classi/dataclass/enum.
  • Suffisso unità esplicito nei nomi: state_mm, volume_l, ec_mscm, temperature_c, theta_volumetric.
  • Costanti maiuscole in cima al modulo: DEFAULT_DEPLETION_FRACTION, KCMAX_DEFAULT.

Tipi

  • Type hints obbligatori su tutte le funzioni pubbliche.
  • Optional[...] esplicito; mai = None implicito su parametri tipizzati senza marcatura.
  • Protocol per duck-typing (vedi io/sensors/protocols.py); preferiti rispetto ad ABC perché non richiedono ereditarietà esplicita.

Dataclass

  • @dataclass(frozen=True) per value object: risultati, eventi, letture sensori, parametri.
  • @dataclass mutabile solo per le entità con stato che evolve nel tempo: Pot, Garden, Room.
  • __post_init__ per validazione fisica all'istanziazione (es. range di pH 0..14).

Errori

  • Eccezioni canoniche con gerarchia chiara (es. SensorError → SensorTemporaryError/SensorPermanentError/SensorDataQualityError).
  • Adapter catturano eccezioni native (urllib, ValueError) e ri-sollevano quelle canoniche per disaccoppiare i chiamanti dai dettagli di trasporto.
  • ValueError per parametri logicamente invalidi; TypeError per type mismatch.

Stile

  • Docstring brevi sopra le funzioni pubbliche; descrivono il perché, non il cosa.
  • Commenti rari, solo dove l'invariante o il vincolo è non ovvio (es. riferimento all'equazione FAO-56).
  • Funzioni < 50 righe; helper estratti quando il flusso si annida oltre 3 livelli.

Cosa NON fare

  • ❌ Importare numpy, pandas, requests nel core (src/fitosim/). Solo in test/demo.
  • ❌ Persistere allerte. Sono viste derivate, sempre ricalcolate.
  • ❌ Mutare campi "immutabili" di un Pot (es. species, substrate): creare un nuovo Pot.
  • ❌ Far dipendere science da domain o io. Le dipendenze sono unidirezionali.
  • ❌ Usare floating-point per equality nei test. Usare pytest.approx con tolleranze esplicite.

9. Glossario tecnico

TermineSignificato
FAO-56Pubblicazione di riferimento FAO "Crop evapotranspiration — Guidelines for computing crop water requirements".
ET₀Evapotraspirazione di riferimento. Domanda atmosferica standard, calcolata su coltura riferimento (rs=70 s/m, h=0.12 m).
ETcEvapotraspirazione colturale. ET₀ × Kc.
KcCoefficiente colturale. Modula ET₀ in funzione della specie e dello stadio fenologico.
Kcb · KeDecomposizione dual-Kc: Kcb traspirazione basale, Ke evaporazione superficiale.
KpCoefficiente di vaso. Modula ETc per materiale, colore, esposizione.
KnCoefficiente nutrizionale. Modula la traspirazione in funzione di EC e pH.
KsCoefficiente di stress idrico. Riduce la traspirazione sotto la soglia RAW.
θFCField Capacity. Contenuto idrico volumetrico al limite superiore (post drenaggio).
θPWPPermanent Wilting Point. Contenuto idrico al limite inferiore (pianta non riesce più ad estrarre acqua).
TAWTotal Available Water = θFC − θPWP.
RAWReadily Available Water = p × TAW (con p depletion fraction). Sotto RAW comincia lo stress.
REW · TEWReadily / Total Evaporable Water dallo strato superficiale (dual-Kc).
WH51 / WH52Sensori Ecowitt di umidità del substrato. WH52 aggiunge temperatura ed EC.
WN31Sensore Ecowitt di temperatura/umidità indoor.
ECConducibilità elettrica del substrato (mS/cm). Proxy della concentrazione salina totale.
CECCation Exchange Capacity. Capacità del substrato di tamponare il pH.
Penman-MonteithEquazione di riferimento per ET. "Standard FAO-56" usa coltura riferimento; "fisica" usa parametri reali della specie.
Hargreaves-SamaniFormula semplificata di ET₀ che richiede solo Tmin/Tmax (fallback robusto).
GDDGrowing Degree Days (gradi-giorno). Temperatura accumulata sopra una soglia base Tbase; guida lo sviluppo fenologico delle annuali indipendentemente dal calendario.

LisimetroMisura diretta dell'ET pesando il vaso: la variazione di massa è l'acqua evapotraspirata. Ground truth del layer di feedback.
